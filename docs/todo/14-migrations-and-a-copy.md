## What you have to do yourself

| | What | Lead time |
|---|---|---|
| 1 | **Run the app once on a machine with `cargo`.** The preflight change is Rust and this environment has no toolchain — it is verified by inspection against `one_shot`'s signature and by matching the supervisor's existing `tsx` invocation, and that is not the same as compiling | minutes |
| 2 | **Delete a stale copy or two, eventually.** Five copies of a growing database is five copies. Nothing prunes beyond `BACKUPS_KEPT` and nothing should — but a person who has been using this for a year may want to look | minutes, once |
| 3 | **Decide whether the copies belong in the same directory as the database.** They are unencrypted, they sit beside it, and a person deleting a project does not reach into them. Moving them under a `backups/` subdirectory would not change any of that; encrypting them needs a key, which needs the Keychain, which is [ADR-0012](../adr/0012-screen-capture-refused.md)'s refusal | a decision, not a task |

## The work

1. ~~**A guard that fails when the schema has moved ahead of the migrations.** *(Open.)*~~
   **Done 2026-09-08, later the same day — `tests/schema-migrations.test.ts`.** The shape was right
   and the worry was not: `--shadow-database-url` takes a temp file, so it is an ordinary vitest
   case in `npm test` rather than a script CI has to remember to run. About four seconds for both
   halves.

   **It has a second half, and that is the half worth reading.** The first case compares the real
   schema against the real migrations. The second manufactures drift — one added field — and
   asserts the guard *notices*, because a comparison that reports "no difference" for the wrong
   reason (a renamed flag, a wrong path, a subprocess that failed in a way that reads as success)
   is a green tick that has stopped meaning anything, which this repository produced twice in the
   week this was written. Verified by hand as well: adding a field to the real schema fails the
   first case with the `migrate dev --name` command in the message.

2. ~~**Generate the baseline and wire `migrate deploy`.**~~ **Done 2026-09-08.**
   `prisma/migrations/0_baseline/` holds 38 tables generated by `migrate diff --from-empty`, so a
   fresh database is created from it and an older one is told it is already there.

3. ~~**Copy the file before migrating.**~~ **Done 2026-09-08.** `backupNameFor` stamps the name so
   copies sort in time order rather than by mtime — a filename that carries its own ordering cannot
   be reordered by a copy that preserves timestamps.

4. ~~**Baseline a database that predates migrations.**~~ **Done 2026-09-08**, and this was the whole
   risk. `migrate deploy` against a `db push` file tries to `CREATE TABLE` over tables that exist
   and dies on the first one; on the day this landed that was every database in the world.

5. ~~**Switch the tray's preflight.**~~ **Done 2026-09-08**, through `tsx`, the same way the
   supervisor already runs the worker, because `scripts/` ships as TypeScript. Item 1 of *What you
   have to do yourself* is the half this cannot claim.

## What this does not cover

- **Rolling back a migration.** There is no `migrate down` in Prisma and this does not invent one.
  The answer to a bad migration is another migration, and the copy taken before it is what stands in
  for an undo — by hand, by a person, deliberately.
- **Restoring a copy automatically.** Refused in ADR-0039: a product that silently restores a backup
  is a product that can silently lose everything done since it was taken.
- **Off-machine backup.** That is a server, and the product argues against having one.
- **Encrypting the copies.** They are exactly as exposed as the database they copy, which is already
  in that directory. Named in ADR-0039's costs rather than solved.
- **The database growing without bound.** Nothing sweeps the ledger on age; a person deletes a
  project ([ADR-0038](../adr/0038-deleting-a-project.md)) or they do not. The copies multiply that
  by up to `BACKUPS_KEPT`, which is worth knowing before somebody wonders where the disk went.
